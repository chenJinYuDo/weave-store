# 012 平面搭配

## 目标

搭配台用衣服抠图按槽位叠成一张平面图。录入时可以选单件，也可以把一整套留在同一张图里。衣橱里已经有的衣服可以推荐成一套。

## 不做什么

- 不把一套衣服拆成上衣、下装或半裙，也不为拆套装调用 DeepSeek。
- 推荐不调用 DeepSeek，不把衣服或生活照发出去。
- 搭配页和成员页不再显示人体，也不再显示垂坠网格。人体和垂坠的代码留在项目里，这一份不删。
- 窄屏只看已保存的平面图，不能拖拽，也不能点推荐。
- 不改布料页。不删除已有的「白衬衫」和「亚麻布」。

## 流程

1. 录入衣服时先拍照。没有照片就点「这是单件」或「这是一套」，都提示「请先拍照」。
2. 「这是单件」仍进入洗标，再抠图并识别草稿。
3. 「这是一套」跳过洗标，只在本地抠图，品类定为「套装」，不请求识别。抠图去掉背景。照片里还有穿着的人时，再去掉头发、脸、手和露出来的皮肤，只留衣服。平铺、没有人的单件仍只去背景。确认页品类固定为套装，名称仍由人填写。
4. 宽屏搭配台把当前叠穿画在同一张 3:4 的图里。有套装时，不再叠上衣、外套、下装、半裙、连衣裙。有连衣裙时，不再叠上衣、下装、半裙，外套、鞋和配饰仍可叠上。
5. 拖入套装时，清掉上衣、外套、下装、半裙、连衣裙。拖入连衣裙时，清掉上衣、下装、半裙、套装。拖入上衣、下装或半裙时，清掉套装和连衣裙。拖入外套时，清掉套装。
6. 点「推荐一套」。能凑出套装、连衣裙，或上衣加下装/半裙时，视口换成这一套并保存。凑不出来时写「还不能凑成一套」，原来的叠穿不动。
7. 窄屏打开搭配，看到「未选择」已保存的那套平面图。没有衣服时写「请在电脑上搭配」。

## 页面

拍照这一步有两个按钮：「这是单件」和「这是一套」。单件后面仍是洗标、正在识别、确认。套装后面是「正在抠图」，然后直接确认。确认页套装的品类不能改。

宽屏搭配仍是三列：衣橱、视口、叠穿。视口上方是成员，旁边是「推荐一套」。视口正文是一张浅底的 3:4 叠图。没有衣服时，图里写「把衣服拖到这里」。不再写「还不能生成人体」「正在生成人体」「正在垂坠」和身高。

叠图从后到前：下装或半裙、连衣裙或套装、上衣、外套、鞋、配饰。套装或连衣裙占据肩到下摆，上衣在上半，外套略大一圈，下装和半裙从腰部开始，鞋在底部，配饰在上角。有抠图就用抠图，没有抠图就写品类。

窄屏标题仍是「搭配」。有已保存的衣服时只显示这张叠图，没有拖拽和「推荐一套」。

成员详情不再放人体视口。正面照、侧面照和表单仍在。

## 数据与接口

品类增加「套装」，顺序为：上衣、下装、半裙、连衣裙、套装、外套、鞋、配饰。筛选和搭配槽位都用这一列。

`POST /api/captures` 增加表单字段 `piece`。`piece=set` 时只抠图，草稿品类是套装，不调用识别。其他值仍走原来的单件识别。

`GET /api/outfits` 和 `PUT /api/outfits` 仍读写槽位。这一份不再为了打开搭配去算垂坠。

`GET /api/outfits/suggest?member_id=` 只读衣橱，返回一套建议，不保存。成员规则与搭配接口相同。建议按这些规则挑，不使用模型：

- 一套可以单独成立，再尽量配上季节合得来的鞋和配饰。
- 否则一件连衣裙，同样可加鞋和配饰。
- 否则一件上衣加一件下装或半裙。季节落在秋或冬时，可以再加外套，以及鞋和配饰。
- 季节相同、是四季或没填季节时加分。颜色相同或有一边没填颜色时加分。
- 几套分数一样时，先套装，再连衣裙，再上下装。
- 一件完整的衣服都凑不出来时，`items` 为空，`message` 为「还不能凑成一套」。

## 验收

1. 录入衣服不拍照就点「这是单件」或「这是一套」，都看到「请先拍照」。单件仍能经过洗标进入确认。衣橱里的「白衬衫」和布料库里的「亚麻布」都还在。
2. 用一张包含整套衣服、而且有人穿着的照片选「这是一套」。确认页品类是套装且不能改，名称可填。抠图里衣服还在，头发、脸、手和露出来的皮肤不在。这次请求没有发往 DeepSeek。保存后衣橱里是一件套装，不是拆开的上衣和下装。
3. 宽屏搭配把已有抠图叠在一张图里，页面上没有「还不能生成人体」和「正在垂坠」。把套装拖进视口后，叠穿里不再同时留着上衣、下装、半裙或连衣裙。
4. 点「推荐一套」。衣橱能凑出一套时，视口换成推荐结果并在刷新后仍在。把衣橱临时看成不能凑套时，页面写「还不能凑成一套」。
5. 窄屏打开搭配，能看到「未选择」已保存的平面图或「请在电脑上搭配」，看不到三列，也看不到人体。成员详情不再出现人体视口。
