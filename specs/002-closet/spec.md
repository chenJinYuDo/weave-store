# 002 衣橱

## 目标

可以手工把衣服记进家里的库，再按条件找出来，也可以改和删。这一份不拍照、不识别。

## 不做什么

- 不建布料、成员、搭配和垂坠的表。
- 不上传照片，卡片上不出现真实图片。
- 不调用 DeepSeek，也不做抠图。
- 所属成员只是衣服上的一段文字，不关联成员档案。

## 流程

1. 衣橱没有记录时，看到「还没有衣服」和主按钮「录入衣服」。
2. 填写名称和品类，其余可空，保存后回到衣橱，并能看见这张卡片。
3. 点卡片进入详情，修改后保存，列表显示新内容。
4. 在详情里删除，确认后这件衣服从列表消失。
5. 筛选是并且关系。没有符合的衣服时，列表区写「没有符合的衣服」，录入按钮仍在。

## 页面

沿用应用骨架的导航、页边距和颜色。

`/closet` 标题「衣橱」。桌面在标题下排一排筛选：品类、颜色、季节、纤维、所属成员。手机上这些收进标题为「筛选」的抽屉，打开抽屉的按钮不是主按钮。主按钮「录入衣服」去 `/closet/new`。

卡片正方形占位底色 `#EFEAE3`，中间是品类。图下是名称、颜色和品类。卡片间距 16px。

`/closet/new` 标题「录入衣服」。字段：名称、品类、颜色、图案、季节、纤维、所属成员。名称和品类必填。主按钮「保存」。

`/closet/:id` 用名称做标题，字段与录入相同，主按钮「保存」。另有「删除」，点开确认「删除这件衣服」。找不到记录时标题「没有这件衣服」，主按钮回到衣橱。

加载中用骨架。加载失败时主按钮是「重试」。

## 数据与接口

SQLite 文件在仓库的 `data/weave.sqlite`，该目录不进 git。衣服表字段：id、名称、品类、颜色、图案、季节、纤维、所属成员、创建时间、更新时间。

品类只允许：上衣、下装、半裙、连衣裙、外套、鞋、配饰。季节只允许空、春、夏、秋、冬、四季。

接口前缀 `/api`：

- `GET /api/garments`，查询参数 `category`、`color`、`season`、`fiber`、`owner`，空值表示不限制，返回数组。
- `POST /api/garments` 新建，返回这件衣服。
- `GET /api/garments/{id}` 单件，没有则 404。
- `PATCH /api/garments/{id}` 修改已有字段。
- `DELETE /api/garments/{id}` 删除，没有则 404。

网页通过开发服务器把 `/api` 转到本机 8000 端口。

## 验收

1. 启动 API 和网页后，衣橱为空时出现「还没有衣服」。
2. 不填名称就保存，衣服不会出现在列表里。
3. 保存「白衬衫 / 上衣 / 白色 / 春 / 棉 / 小陈」后，卡片上能看到这些字。
4. 把品类筛成「外套」时，白衬衫消失，并看到「没有符合的衣服」。筛回全部后它还在。
5. 把名称改成「蓝衬衫」并保存，列表变成蓝衬衫。
6. 删除并确认后，列表回到「还没有衣服」。
7. 打开不存在的 `/closet/missing`，能看到「没有这件衣服」。
8. 数据库里没有布料表，页面上的布料仍是原来的空壳。
